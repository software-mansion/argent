A Mac has four sessions. A session is one isolated part of a Mac, with its own macOS user, disk volume and resources. `sim-remote login` reserves a session, and `sim-remote release` gives it back. See [How it works](/docs/cloud/fundamentals/how-it-works#macs-and-sessions).

## Lifecycle

| Event        | Trigger                                      | Effect                                                                                        |
| ------------ | -------------------------------------------- | --------------------------------------------------------------------------------------------- |
| Login        | `sim-remote login`                           | The server checks the API key and returns a login token. The daemon holds the token in memory |
| Acquire      | `login` without `--no-acquire`, or `acquire` | The server reserves a free session of your team for you                                       |
| Attach       | `attach <MACHINE_ID>`                        | The daemon switches to another session that you already hold. Open tunnels close              |
| Release      | `release`                                    | The session returns to your team. You stay logged in                                          |
| Logout       | `logout` or `daemon stop`                    | The session returns to your team and the daemon forgets the token                             |
| Idle release | No command for the idle timeout              | The daemon releases the session on its own. You stay logged in                                |
| Lifetime cap | The session is held for the maximum lifetime | The server releases the session                                                               |

When a session returns to your team, Argent Cloud revokes its credentials, closes the live connections, erases the simulators, and rebuilds the session volume from a clean image.

## Limits

| Limit                       | Value                                         | Notes                                                                                            |
| --------------------------- | --------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| Idle release                | 900 seconds (15 minutes)                      | Set `SIM_REMOTE_IDLE_TIMEOUT_SECS` to change it. The server has its own idle limit of 16 minutes |
| Maximum time on one session | 24 hours                                      | Enforced by the server                                                                           |
| Login token                 | 24 hours                                      | Run `sim-remote login` again after it expires                                                    |
| Wait for a free session     | 1800 seconds by default, 3600 seconds maximum | `--timeout` sets the client value. The server caps it                                            |
| Upload size                 | 1 GiB                                         | Applies to every file that `sim-remote` uploads                                                  |
| Sessions per user           | More than one                                 | Each `acquire` reserves one more session                                                         |

## Simulators per session

| Limit                         | Value                                   |
| ----------------------------- | --------------------------------------- |
| Sessions per Mac              | 4                                       |
| Booted simulators per Mac     | 6 in total, shared by its four sessions |
| Booted simulators per session | 2, including the pre-booted simulator   |

A session stays responsive with up to two booted simulators. To run more simulators at the same time, hold more than one session and boot at most two simulators in each. For six simulators, use three or four sessions. See [Several sessions on one computer](#several-sessions-on-one-computer).

A new session has one pre-booted simulator by default. Shut it down before you boot two other simulators. The pre-booted simulator is a setting of your account. [Contact us](https://argent.swmansion.com/cloud#contact) to turn it off or to change the device. Without it, the first boot is slower.

With more than two booted simulators, the session can stop starting new processes. The session does not recover from the client. See [Troubleshooting](/docs/cloud/reference/troubleshooting#symptoms).

## The daemon

`sim-remote` runs a small background daemon on your computer. The daemon holds the login token, sends a heartbeat to the server every 60 seconds, and owns the tunnels. Any command that needs a login starts the daemon. The daemon is the same binary as the CLI.

| Item             | Value                                                                                                 |
| ---------------- | ----------------------------------------------------------------------------------------------------- |
| Socket           | `$HOME/.sim-remote-daemon.sock`, or `$HOME/.sim-remote-daemon-<NAME>.sock` for a named daemon         |
| Idle check       | Every 60 seconds                                                                                      |
| Stop             | `sim-remote daemon stop`. This releases the session and logs you out                                  |
| Version mismatch | After an update, the old daemon refuses the new client. Run `sim-remote daemon stop` and log in again |

The daemon keeps the login token in memory. `sim-remote` writes no login token, API key or configuration file to disk. The log files below are the only files that `sim-remote` writes.

## Several sessions on one computer

One daemon works with one session at a time. Set `SIM_REMOTE_SESSION` to a name to use several sessions at the same time from one computer. Each name has its own daemon and its own login.

```bash
export SIM_REMOTE_SESSION=agent-1
sim-remote login
```

All `sim-remote` commands that run with the same value share one daemon. A different value is a different daemon. Commands that run without the variable use the default daemon.

| Rule       | Value                                                       |
| ---------- | ----------------------------------------------------------- |
| Characters | Lowercase letters, digits, `.`, `_` and `-`. No leading `.` |
| Length     | 1 to 32 characters                                          |
| Socket     | `$HOME/.sim-remote-daemon-<NAME>.sock`                      |
| Log file   | `sim-remote-daemon-<NAME>`                                  |
| Scope      | `daemon stop` and `logout` act only on the named daemon     |

Every process reads the variable from its own environment. Set `SIM_REMOTE_SESSION` in the shell or agent that runs the commands. Every shim and tool that it starts inherits the same value.

## Log files

`sim-remote` writes its log to a file and echoes only errors to stderr.

| Platform | Directory                                                    |
| -------- | ------------------------------------------------------------ |
| macOS    | `~/Library/Logs/radon/`                                      |
| Linux    | `$XDG_STATE_HOME/radon/logs`, or `~/.local/state/radon/logs` |

`sim-remote` rotates the log file daily and keeps 7 days. Set `RUST_LOG` to change the filter. A named daemon writes to `sim-remote-daemon-<NAME>`.
