`sim-remote` prints `error: <message>` on stderr. When there is an action to take, a second line `  hint: <advice>` follows, with two leading spaces. The exit code is `1`.

## Error messages

| Message                                                        | Cause                                                        | Action                                                                                                                    |
| -------------------------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| `not logged in`                                                | The daemon holds no login token                              | Run `sim-remote login`                                                                                                    |
| `your session is no longer valid`                              | The login token expired, or the API key was replaced         | Run `sim-remote login`                                                                                                    |
| `authentication failed: <detail>`                              | The server rejected the API key                              | Check `SIM_REMOTE_API_KEY` or `--api-key`                                                                                 |
| `client/server protocol mismatch: <detail>`                    | The binary is too old for the server                         | Download the latest release of `sim-remote`                                                                               |
| `no simulator is available right now`                          | All sessions of your team are busy                           | Run the command again with `--timeout <SECS>` to wait for a free session                                                  |
| `you no longer hold a machine`                                 | The session was released, for example after the idle timeout | Run `sim-remote acquire`, or `sim-remote attach <MACHINE_ID>` for a session that you still hold                           |
| `your machine is offline`                                      | Your session lost its connection to the server               | Wait a few seconds and run the command again. If it stays offline, run `sim-remote release` and then `sim-remote acquire` |
| `you do not hold that machine`                                 | The session ID given to `attach` is not yours                | Run `sim-remote list-machines` to see the sessions that you hold                                                          |
| `the server is busy right now`                                 | The server rate limits your requests                         | Wait a moment and run the command again                                                                                   |
| `could not reach sim-router at <URL>`                          | No connection to the server                                  | Check your network and the `--server` URL                                                                                 |
| `the request to sim-router timed out`                          | The server did not answer in time                            | Run the command again                                                                                                     |
| `the sim-remote daemon is not responding: <detail>`            | The daemon on your computer is stuck                         | Run `sim-remote daemon stop`, then run the command again                                                                  |
| `upload exceeds the 1 GiB limit`                               | The file is too large                                        | Reduce the size of the bundle or the file                                                                                 |
| `simulator operation failed: <detail>`                         | `simctl` on the Mac failed                                   | Read the detail. It is the message of `simctl`                                                                            |
| `the running daemon is incompatible with this client`          | You updated `sim-remote` while the old daemon ran            | Run `sim-remote daemon stop` and log in again. This releases the session                                                  |
| `SIM_REMOTE_SESSION="<value>" is not a valid session name`     | The name has characters that `sim-remote` does not accept    | Use 1 to 32 lowercase letters, digits, `.`, `_` or `-`, with no leading `.`                                               |
| `no sim-router URL: pass --server <URL> or set SIM_ROUTER_URL` | The binary has no server URL                                 | Use the release binary, or pass `--server <URL>`                                                                          |

## Symptoms

**`login` stays on `Waiting for an available machine...`.** All sessions of your team are in use. Wait, or shorten the wait with `--timeout <SECS>`, or fail at once with `--no-wait`. Run `sim-remote list-machines` to check whether you hold a session yourself.

**A simulator that you booted earlier is gone.** The daemon is attached to another session, or the session was released and rebuilt. Run `sim-remote list-machines` to see the current session and `sim-remote attach <MACHINE_ID>` to switch back. After a release, boot the simulator again.

**Commands fail with `Resource temporarily unavailable (os error 35)`.** The session has more than two booted simulators and cannot start new processes. The message often comes after `failed to spawn xcrun:` or `tar extract:`. The session does not recover on its own. `simctl shutdown` also fails, because it must start `xcrun`. Run `sim-remote release` and then `sim-remote acquire` to get a clean session. Argent Cloud resets the released session in about a minute. Boot at most two simulators in each session. See [Sessions and limits](/docs/cloud/reference/sessions#simulators-per-session).

**The app in the simulator cannot reach your local server.** The simulator has no route to your `localhost`. Run `sim-remote reverse start <UDID> <PORT>` and confirm the tunnel with `sim-remote reverse status`. See [Connect to local servers](/docs/cloud/guides/local-servers).

**The app crashes on the hosted simulator.** The crash report is a file on the Mac. Run `sim-remote logs <UDID> --process <BUNDLE_ID>` to download the crash reports and the recent logs of the app. See [Get crash reports and logs](/docs/cloud/guides/logs).

**Argent shows no hosted simulators.** Argent needs `sim-remote` on `PATH` and a session that you hold. Run `sim-remote login` and list the devices again.

**The session was released while a test ran.** The idle timeout expired because no `sim-remote` command ran for 15 minutes. Run `sim-remote keepalive <TIME>` next to the test, or increase `SIM_REMOTE_IDLE_TIMEOUT_SECS`. See [Sessions and limits](/docs/cloud/reference/sessions).

**Maestro or Appium cannot start the test runner.** Read the log of the `xcodebuild` process: `xctest_runner_*.log` for Maestro, or the Appium server log with `appium:showXcodeLog: true`. The shim writes its steps there. See [Maestro](/docs/cloud/integrations/maestro) and [Appium](/docs/cloud/integrations/appium).
