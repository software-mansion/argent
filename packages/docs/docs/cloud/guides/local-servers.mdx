The hosted simulator cannot reach the `localhost` of your computer, and your computer cannot reach the `localhost` of the Mac. `sim-remote` provides one tunnel command for each direction.

## Reverse tunnels

A reverse tunnel lets the simulator reach a server on your computer. The app in the simulator connects to `localhost:8081`, and the traffic arrives at port 8081 on your computer. Use a reverse tunnel for a local Metro bundler, a mock API or a staging proxy.

```bash
sim-remote reverse start <UDID> 8081
```

Argent opens a reverse tunnel for Metro and for the debugger on its own. See [Argent](/docs/cloud/integrations/argent).

## Forward tunnels

A forward tunnel lets your computer reach a server on the Mac, for example a test runner next to the simulator. Most apps do not listen on a port, so most apps need a reverse tunnel only. The command below binds port 9000 on your computer and sends the traffic to port 8000 on the Mac.

```bash
sim-remote forward start <UDID> 9000:8000
```

A forward tunnel reaches only the servers that your own session started.

:::warning
The sessions on one Mac share its network interfaces, so only one simulator on the Mac can bind a given port. A server on a fixed port fails to start when another simulator already holds that port. Make the server request port 0, read the port that the system assigns, and forward to that port.
:::

## Lifetime

The daemon keeps each tunnel open between commands. A tunnel closes when you release the session or when the daemon switches to another session. Run `sim-remote reverse status` or `sim-remote forward status` to list the open tunnels.

The [CLI reference](/docs/cloud/reference/cli#tunnel-commands) lists the `reverse` and `forward` commands.
