Argent drives a growing set of targets through a single toolkit, each with the right interaction model.

| Platform          | Targets                                                                 | Interaction      |
| ----------------- | ----------------------------------------------------------------------- | ---------------- |
| **iOS**           | Simulators, and physical iPhones                                        | Touch / gesture  |
| **Android**       | Emulators (AVDs) and physical devices over adb                          | Touch / gesture  |
| **TV**            | Apple TV (tvOS), Android TV / Google TV, Amazon Fire TV (Vega)          | D-pad / remote   |
| **Desktop & web** | Electron and Chromium apps (incl. React Native Web / Expo web) over CDP | Mouse / keyboard |
| **HarmonyOS**     | Phones over `hdc`, and DevEco Studio emulator instances                 | Touch / gesture  |

## Touch targets

iOS simulators and Android emulators or devices are driven with taps, swipes, pinches, rotations, hardware buttons and typed text. Coordinates always come from a discovery pass over the accessibility or component tree, never from a screenshot.

### Foldable simulators and emulators

Argent drives these foldable devices closed, half-open and open:

- The iPhone Duo simulator.
- A foldable Android emulator, for example a Pixel Fold or a generic foldable AVD.

The agent folds and unfolds the device with the `fold` tool. `list-devices` marks a foldable device with `foldable: true`. Screenshots, element trees, taps and recordings use the panel that shows the UI. Argent cannot fold a physical Android device. See the [tools reference](/docs/reference/tools).

### Emulators started by another user

Argent finds an emulator through a discovery file that the emulator writes in a directory of its user:

- On macOS, the directory is in the home directory.
- On Linux, the directory is in `$XDG_RUNTIME_DIR` or `/run/user/<uid>`, and in the home directory only when neither exists.

Argent does not find the file of an emulator that another user started. On macOS, Argent also does not find the file when the same user started the emulator with another `HOME`. Argent then controls that emulator over adb, the same way as a physical Android device. This path has these limits:

- Two-finger gestures (pinch, rotate, a two-finger `gesture-custom`) fail with an error. On this path, Android keeps both fingers down after the gesture and refuses all later touches.
- Screenshots have a lower resolution than on an emulator that Argent finds. `screenshot-diff` reports a size mismatch when it compares screenshots from the two paths.
- Only one Argent tool-server can control the emulator. When a second tool-server connects, the first one loses its connection and connects again on its next call.
- Argent copies its screen-sharing agent to `/data/local/tmp/.studio` on the emulator and keeps it there for the next start.
- A touch turns off auto-rotate on the emulator. Argent sets auto-rotate back when it stops controlling the emulator. If the tool-server crashes, or two tool-servers take turns on the emulator, auto-rotate can stay off. To turn it on again, run `adb -s <serial> shell settings put system accelerometer_rotation 1`.

`shake` and `fold` fail on an emulator that another user or another `HOME` started. These tools use the emulator console, and the console accepts only the auth token from the home directory of the emulator.

To remove these limits, stop the emulator from the account that started it. Then start it with `boot-device`, or with the same user and `HOME` as Argent. `boot-device` reuses an emulator that is already running, and `boot-device` with `force` cannot stop this emulator.

### Physical iPhones

Argent also drives a physical iPhone over a USB cable. Physical iPads are not supported yet. Automation on hardware is scoped to one app at a time, and a subset of the simulator tools is available. See [Physical iOS devices](/docs/features/physical-ios-devices).

### HarmonyOS

HarmonyOS support is experimental and off by default. Run `argent enable harmonyos` to turn it on. While the flag is off, `list-devices` shows no HarmonyOS target and Argent refuses every `harmony-` id. See [Feature flags](/docs/reference/configuration#feature-flags).

Argent drives any HarmonyOS phone or emulator that `hdc` is connected to. A phone with USB debugging enabled appears as `harmony-<connectKey>`. A DevEco Studio emulator instance appears as `harmony-emulator-<name>`. `boot-device` starts the instance and returns its `harmony-<connectKey>` id, so the same tools drive a phone and an emulator.

- Argent reads the screen and injects taps, swipes and text through the device's own `uitest`.
- `gesture-pinch` sends the start and end points of both fingers in one `uinput` call. The device interpolates the movement.
- `launch-app`, `restart-app` and `open-url` use the `bm` and `aa` shell commands.
- `reinstall-app` installs a single `.hap` file with `hdc uninstall` and `hdc install`.
- Argent refuses `gesture-rotate` and `gesture-custom`. The device moves each contact along one straight line per call.
- Argent also refuses `rotate`, the profilers and the debugger. The device has no orientation command, and the profilers and the debugger have no HarmonyOS ingest path.

Huawei restricts the emulator image download to mainland China. Outside mainland China, you cannot create an emulator instance until you get an image.

## TV targets

A TV UI is focus-driven rather than touch-driven. Argent reads which element currently holds focus, then moves the cursor with directional remote presses and confirms with select.

## Desktop and web targets

Electron apps and Chromium browsers exposing the Chrome DevTools Protocol are driven with mouse clicks, wheel scrolling and drags. Argent can also walk the DOM, manage tabs, read and write cookies and storage, and inspect network traffic.

## React Native

Argent works with React Native apps out of the box, so your agent can build, launch and iterate on a React Native project the same way it would any native app, with no extra setup.
