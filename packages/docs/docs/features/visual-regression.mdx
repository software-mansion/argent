Visual regression testing finds unwanted changes in the look of the app. Argent supports two types of checks:

- **Snapshot tests**: a `snapshot` step in an [e2e test](/docs/features/e2e) compares the screen with a stored baseline. The step runs in CI without an agent.
- **Screenshot tests by the agent**: the agent compares two screenshots and tells you which areas and which text changed.

Use a visual check after a change to the layout, the spacing, the colors, the typography, the icons or the images.

## Quick start

1. Save this e2e test as `.argent/e2e/home.yaml`. Replace `com.example.app` with the app id of your app, and `home-screen` with an id or a text from its first screen.

   ```yaml
   steps:
     - launch: com.example.app
     - await: { visible: { id: home-screen } }
     - snapshot: home
   ```

2. Write the baseline from a known-good state of the app:

   ```bash
   argent e2e run home --update-baselines
   ```

   When more than one device is booted, add `--platform ios` or `--device <id>`.

3. Review the baseline in `.argent/e2e/__baselines__/home/` and commit it.
4. Run the check. The command exits non-zero when the screen does not match the baseline:

   ```bash
   argent e2e run home
   ```

5. In CI, add `--output` to keep the baseline, current and diff images of each failed snapshot for an artifact upload:

   ```bash
   argent e2e run home --output e2e-artifacts
   ```

## Baselines in e2e tests

A `snapshot` step captures the screen and compares it with the baseline of the step.

- The step fails when no baseline exists. Run the e2e test with `--update-baselines` to write the baselines.
- The step fails when the difference is above a tolerance. You can set the tolerance for each step.
- The step can compare one element only instead of the full screen.
- Before the capture, the step waits until the screen stops changing.
- Argent writes the diff image only when the step fails.
- The step compares pixels only. It does not read the text with OCR.

Ask the agent to add the step, for example: "Add a snapshot step to the checkout e2e test for the summary screen."

## Comparisons by the agent

The agent compares two screenshots with the `screenshot` and `screenshot-diff` tools. Each side is a saved screenshot or a live capture of the device. A typical sequence:

1. The agent brings the app to a known state and captures a baseline screenshot.
2. You make the change, or the agent does the interaction.
3. The agent compares the live screen with the baseline.
4. The agent reports the result. The report includes a change that you did not ask for.

The summary of the comparison contains three parts:

| Part           | Content                                                                                         |
| -------------- | ----------------------------------------------------------------------------------------------- |
| Overall status | Unchanged or changed, and the percentage of pixels that are different                           |
| Changed areas  | The position and size of each area that changed, and the direction of the color change          |
| Text changes   | Text that appeared, disappeared, moved, or changed its content, its font, its size or its color |

When pixels differ, Argent reads the text of both screenshots with OCR. Thus the agent knows that the label "Save" became "Saved". Argent also writes a diff image that marks the brighter pixels, the darker pixels and each changed area.

Example instructions:

- "Capture a baseline of the settings screen. Then apply my change and compare."
- "I changed the font of the headings. Make sure that nothing else on the screen changed."

## Limits

- The comparison needs a stable screen. Animation, a live clock, advertisements or random data make the comparison noisy.
- Both screenshots must come from the same device model, in the same orientation and at the same scale.
- On a phone, Argent removes the status bar from the comparison of a full screen.
- A visual check does not replace a check of the accessibility tree, the logs or the network record.
- The `snapshot` step works on each platform where Argent captures screenshots, Chromium and Vega included.
- Comparisons by the agent work on an iOS simulator, an Android emulator or device, a HarmonyOS device and a [Mac app](/docs/features/mac-apps). They do not work on Chromium, Apple TV or Vega apps.
- On a [physical iPhone](/docs/features/physical-ios-devices), the agent captures full-resolution screenshots and compares them on the host.

See [Snapshots](/docs/reference/e2e-yaml#snapshots) in the e2e YAML reference for the step options and the baseline keys. See the [tools reference](/docs/reference/tools) for `screenshot` and `screenshot-diff`.
