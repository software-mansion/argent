# Network inspection

Argent records the HTTP requests your app sends. Ask your agent to find a failed request, inspect its headers and payload, or compare responses before and after a change.

## Choose which traffic to inspect

- **React Native**. Inspect JavaScript requests, including React Native and Expo fetch, and XMLHttpRequest calls such as axios. The app needs a development build connected to Metro.
- **iOS simulators and Mac apps**. Inspect HTTP requests from URLSession and NSURLConnection, including requests from native modules. Background URLSession transfers and web views are outside this capture.
- **Android**. Inspect OkHttp requests in a debuggable app. Android 8 has [limited coverage](/docs/reference/tools#native-network-capture-on-android).
- **Chromium and Electron**. Inspect the active tab, including page requests and assets.

Argent can inspect HTTPS without a proxy or a certificate. One request can appear in both JavaScript and native logs. An empty log only describes the traffic that the selected capture can see.

## Start and stop the capture

Ask your agent to start capture, repeat the action that sends the requests, then inspect the log. On iOS simulators, Android, and Mac apps, the agent can start JavaScript and native capture together or separately. On Vega, reading the JavaScript log starts capture. Argent records traffic when it connects to a Chromium or Electron page. Start and stop mark a window for request checks on these targets. The log keeps recording.

A JavaScript reload or app restart clears the JavaScript log. Start capture again before repeating the action. On Vega, read the log again. Argent can resume native capture when it relaunches the app. Capture can miss startup requests. On an iOS simulator where the device provider controls native capture, a restart ends the capture and clears its history. Check native capture [on Android](/docs/reference/tools#native-network-capture-on-android) or [on iOS and Mac apps](/docs/reference/tools#native-network-capture-on-ios-and-mac-apps) before trying to capture startup traffic.

Stopping capture keeps the requests already recorded. Read any Android native bodies you need before stopping. Native capture can affect profile timings. Ask the agent to stop it and restart the app before profiling, or turn it off in the device provider if it owns the capture.

## Wait for a request

Ask the agent to check that an action sends the expected request. For example, check that tapping Sign In sends a POST and receives a successful response. The agent starts capture before the action and can find the response even if it has already finished. If the check misses, Argent can show requests with a different status or URL. You can record the check in an [e2e test](/docs/features/e2e).

## Read request details

The agent can read a request's URL, status, duration, headers, and available bodies. Argent redacts sensitive header values. Where a [secret](/docs/reference/configuration#secrets) you gave Argent appears, the agent sees its placeholder, such as `{{secret:APP_PASSWORD}}`, in place of the value. Other credentials still show, for example a token that the server issues. Treat the log as app data.

Capture keeps a recent history and shows previews of large bodies. Read native bodies before the app exits or restarts if you need them for a comparison.

## Network conditions

Ask your agent to slow the network or go offline to test loading states, retries, and error handling.

- **Local iOS simulators**. Add latency, limit speeds, or go offline for one app's URLSession traffic. The app bypasses its HTTP cache while Argent shapes or inspects requests.
- **Android emulators**. Add latency or limit speeds for traffic that uses the system proxy. Offline mode disables Wi-Fi and mobile data. Ports forwarded with `adb reverse` stay reachable, and Ethernet can prevent offline mode. Provider emulators support only offline mode and reset.
- **Chromium and Electron**. Add latency, limit speeds, or go offline for the active tab's page.

Network conditions are unavailable on physical devices and remote iOS simulators. Ask the agent to restore normal networking after each test. Android offline mode persists after Argent stops. See the [network conditions reference](/docs/reference/tools#network-conditions) for platform behavior and recovery.

## Example instructions

- "Start capture and sign in. Show me the sign-in response and any requests that failed."
- "Compare the request payload before and after my change."
- "Slow the network and show me the loading state of the feed."

See the [tools reference](/docs/reference/tools#network-capture-on-ios-android-and-mac-apps) for capture options and platform limits.
